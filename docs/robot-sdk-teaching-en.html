Robot SDK 1.5.0 · 2026-11-04

Teaching, recording and trajectory export

robot.startTeach().throwIfError();       // Enter drag teaching and record
robot.stopRecording().throwIfError();    // Freeze the recording and keep drag mode
robot.stopTeach().throwIfError();        // Exit teaching and command a position hold
robot.saveTrajectory("teach.json").throwIfError(); // Export to a client-side file

In Python, use start_teach(), stop_recording(), stop_teach() and save_trajectory(local_path). Check results with raise_for_error(). The corresponding C functions are robot_session_stop_recording and robot_session_save_trajectory. The CLR methods are StopRecording() and SaveTrajectory(localPath).

Recording and position hold

startTeach() sets the selected arm to gravity compensation and starts sampling. Starting again after sampling has stopped replaces the previous recording. Calling it during an active recording keeps the current RT recording. Both startTeach() and stopRecording() wait for an acknowledgement and execution feedback. Recent RT versions confirm execution using the command sequence number. Older RT versions without command-correlation fields wait for three consecutive fresh feedback frames, which cannot confirm execution of a specific command.

stopRecording() freezes the samples in RT memory and leaves drag mode active. Playback, file export and starting a new recording are separate operations.

stopTeach() can end an active recording or follow stopRecording(). It switches to joint position targets, preserves the configured low-level position or velocity execution mode, and waits for fresh feedback before sending a short hold command. The call fails if the mode change or hold command is rejected, or if feedback times out. An acknowledgement confirms command acceptance. Use waitUntilIdle() if the application needs to wait for the motion state to end. The RT controller and drives handle the transition from torque to position control. Verify the transition on the robot.

Exporting a trajectory

saveTrajectory(local_path) exports frozen samples from drag mode or after teaching ends. It leaves motion and recording state unchanged. Possible errors include MotionInterrupted while recording is active, CommandInvalid when there are no samples, Unsupported when RT lacks the export service and TransportUnavailable when the TCP channel is unavailable.

Methods on Robot select arm(0). Use arm(i).saveTrajectory(path) to export samples for a specific arm. The UDP teaching_cmd field controls sampling for the whole robot. On a dual-arm robot, call stopTeach() on each arm to exit drag mode on both arms. Each call sets position hold for the selected arm.

Export uses the optional TCP Teach service (service ID 2, method 1). The SDK reads metadata, then fetches samples in batches of up to 256. RT checks the recording version to avoid mixing samples from different recordings. Network transfer and file writes run without holding the motion-send lock. The SDK replaces the target file only after a complete export and removes the temporary file if export fails.

The JSON format is robot_sdk.teaching_trajectory with version: 1. Fields include arm_index, recording_id (string), joint_count, sample_period_sec, sample_count, position_unit: "rad" and positions. Each row contains the raw RT positions for the arm joints at one sample. Multiply the zero-based row index by the sample period to obtain the sample time. The file excludes gripper samples.

resetPlayback() and startPlayback() use the recording in RT memory. File import, playback from an exported file and recovery after power loss are unsupported.
